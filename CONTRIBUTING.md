# Contributing to GUB Developers Community

Thanks for your interest in contributing! This guide is designed for beginner developers.

## Before You Start

- Read the [Code of Conduct](CODE_OF_CONDUCT.md).
- Check open issues before creating a new one.
- If you are unsure where to begin, look for beginner-friendly issues.

## Contribution Workflow

1. **Fork** the repository.
2. **Clone** your fork locally.
3. Create a new branch from `main`.
4. Make focused changes.
5. Commit with clear messages.
6. Push your branch and open a pull request.

## Branch Naming

Use descriptive branch names:

- `docs/update-roadmap-web`
- `resource/add-free-js-course`
- `project/idea-campus-event-app`
- `fix/typo-in-contributing`

Pattern: `<type>/<short-description>`

## Commit Message Tips

Use short, clear messages:

- `docs: add AI/ML roadmap section`
- `resources: add free Git learning links`
- `fix: correct typo in project ideas`

## Pull Request Guidelines

Before opening a PR, make sure:

- [ ] Your changes are relevant and focused.
- [ ] You updated related docs if needed.
- [ ] You checked formatting and links.
- [ ] You explained why the change is useful.

In your PR description, include:
- Summary of changes
- Why the change is needed
- Any related issue (for example: `Closes #12`)

## Code Review Process

- Maintainers/reviewers will check clarity, usefulness, and consistency.
- You may receive feedback — this is normal and part of collaboration.
- Update your branch based on feedback.
- Once approved, your PR can be merged.

## Need Help?

Open an issue with your question. We encourage respectful, beginner-friendly discussion.
