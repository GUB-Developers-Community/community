# Contributing to GUB Developers Community

Thank you for helping make the GUB Developers Community more useful and welcoming. Contributions of all sizes are valuable, including documentation fixes, resource suggestions, project ideas, and code.

## Before You Start

- Read the [Code of Conduct](CODE_OF_CONDUCT.md).
- Search existing issues and pull requests before starting work.
- For a large change, open an issue or discussion first so the community can align on the idea.

## Contribution Workflow

1. Fork the repository.
2. Create a focused branch, such as `docs/add-python-resources` or `feature/event-template`.
3. Make your changes and keep each pull request focused.
4. Check links, spelling, formatting, and file paths before committing.
5. Commit with a clear message.
6. Push the branch to your fork and open a pull request against `main`.

## Documentation Guidelines

- Use Markdown and follow the style of nearby files.
- Prefer clear headings, short paragraphs, and practical examples.
- Use relative links for pages inside this repository.
- Add sources when recommending external resources.
- Do not include private information, credentials, or content that you do not have permission to share.

## Pull Requests

Describe what changed and why. Include screenshots or examples when they make a documentation or user-facing change easier to review. Maintainers may request revisions so that contributions remain consistent, accurate, and accessible.

## Questions

If you are unsure where to begin, browse the [project ideas](projects/project-ideas.md), suggest an improvement in a GitHub Discussion, or open an issue describing what you would like to work on.
